Bitchat is an open-source app that lets two phones exchange encrypted messages over Bluetooth — no SIM, no internet, no server, no phone number. I built an extension that gives it a real Monero wallet, so the same offline mesh that carries a text message can now carry a private payment. No bank in the middle. No signal required.

The Premise

If a Mesh Can Carry a Sentence, It Can Carry a Transaction

Bitchat is a decentralized messaging app from the team at permissionlesstech — phones talk directly to each other over Bluetooth LE, relaying messages hop-by-hop across a mesh with no cell tower, no Wi-Fi, and no company server reading along. It works in a subway tunnel, at a festival with a jammed network, or anywhere connectivity is the whole problem.

Monero solves an adjacent problem for money: private, untraceable transactions with no bank, card network, or payment processor sitting in the middle. Put those two ideas next to each other and the extension writes itself — a mesh that already moves encrypted data phone-to-phone doesn't need much convincing to move value the same way.

💭
Worth saying plainly

This is a personal fork, not an official Bitchat release — the with-monero branch on github.com/niyid/bitchat-android. The upstream project at permissionlesstech/bitchat-android doesn't include Monero support, and this isn't affiliated with that team. It's an extension built on top of their excellent mesh, credited accordingly.

The Extension

What Actually Got Built

Nothing about Bitchat's core mesh, encryption, or UI was replaced. The wallet plugs in as a new capability riding on the transport and screens that already exist — roughly 5,100 lines across a dozen new files, wired around a real Monero wallet library (the same xmrwallet JNI bindings behind the well-known Monerujo wallet app).

Send & Sign

On-device wallet

Transactions are built and signed on the phone itself, through a locked-down state machine that won't let two sensitive operations overlap and corrupt the wallet.

💬
Feels Like Chat

Payments as messages

A payment shows up as a chat bubble in the same thread as your conversation — no separate "pay" app, no context switch, no new account to set up.

🔍
Trust, But Verify

Independent confirmation

The recipient doesn't have to take the sender's word for it — their app checks multiple Monero nodes in parallel to confirm the payment actually landed.

🔒
Locked Down

Encrypted credentials

Node usernames and passwords are stored in EncryptedSharedPreferences, not plaintext — one of several hardening passes this fork went through.

Straight Talk

Working Core, Labelled Edges

A working prototype that hides its rough edges isn't very useful to anyone — so here's the honest version. The primary send path — build, sign, broadcast, confirm — is solid and tested end-to-end. A secondary path for moving transactions as raw data blobs across the mesh (useful when neither phone can reach a Monero node at all) is still a stub.

🔧
The one architectural item on the list

The Bluetooth layer currently runs a second, parallel GATT server alongside Bitchat's own — functional, but not how it should ship long-term. The right fix is folding it into Bitchat's existing Bluetooth stack rather than running two side by side, and that's the next piece of work.

Closing Thought

The Mesh Was Always Capable of More Than Chat

Bluetooth mesh messaging and private cryptocurrency both exist independently, and neither one is new. What's interesting is how little new infrastructure it took to graft one onto the other — the mesh, the encryption, the peer discovery, and the chat UI were already there, built for text. A payment, it turns out, is structurally just a message with a different payload.

A mesh built to carry a sentence can be taught to carry a transaction. The idea was never the hard part — making sure the wallet on the other end doesn't fall over is.
